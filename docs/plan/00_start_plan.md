# 项目方案：逐个机制实现（机制阶梯）

- 日期：2026-09-30（用户暂时同意这个方向，后续可以修正）
- 原则（用户）：
  1. 在能实现目标机制的前提下尽量复用已有资源，但不为了靠近某个示例而偏离自己的路线；
  2. **一次只做一个机制**，每个机制想清楚、验证好、用户理解并认可之后，再做下一个。
- 已定的事项：3D 组织；先刚性针；组织用共旋线弹性；参数先用文献值；速度 = 动画不卡顿、接近真实穿刺速度（每步计算时间 ≤ dt）。
- 暂缓的事项："破裂"的定义（做到刺穿和切割时再定）、柔性针模型（做到柔性针时再定）、正式的组织参数（以后问 Manish）。

## 每个机制都走同样的六步
| 步骤 | 内容 | 产出 |
|---|---|---|
| ① 定义物理 | 这个机制在物理上是什么、公式、应该看到的现象（依据文献） | 一页说明，写给用户看 |
| ② 预测结果 | 事先写下可以检验的预期（量级、随什么变化） | 预期清单 |
| ③ 最小场景 | 只打开这一个机制 | 小场景 |
| ④ 实现 | 现有实现符合物理就用，不符合就自己写（不改上游插件源码，改动写在我们自己的代码里） | 代码 |
| ⑤ 验证 | 用实验对照预期；用户可以在 SOFA 窗口里看动画 | 数据、图、结论 |
| ⑥ 用户确认 | 用户理解并认可后才进入下一个机制 | — |

## 机制阶梯
| 顺序 | 机制 | 只关心什么 | 现有资源（已知情况） |
|---|---|---|---|
| 0 | 地基：组织力学、针的驱动、约定和速度 | 组织在已知载荷下的变形对不对；针能否按真实速度准确跟随给定轨迹；单位和力的读法；实时 | SOFA 共旋力场可以用；官方场景的一阶针和针根驱动方式要改 |
| 1 | Tenting（刺穿前组织凹陷） | 针尖和表面的单边接触；力随压入深度的变化；作用力 = 反作用力 | 插件的 `ConstraintUnilateral`（Signorini）可能可以直接用，需要单独验证 |
| 2 | 刺穿（阈值 → 状态切换） | 切换发生在什么力下；不随 dt 变化；切换后的回弹 | 插件有机制，判定量要改成法向力 |
| 3 | 插入导向（横向约束，先不加摩擦） | 针沿针道走；约束点生成；求解器收敛 | 插件框架可以用；约束间距按单元尺寸 |
| 4 | 摩擦 | 阻力随插入长度线性增长；粘着和滑动；拔出反向 | 插件的"摩擦"不符合物理，要自己写 |
| 5 | Cutting（针尖切割阻力） | 刺穿后的力骤降；切割阻力大小 | 插件没有，要自己写；到这一步再定"破裂"的定义 |
| 6 | 拔出和反复插拔 | 约束点删除；再次插入 | 插件有，但有已知问题 |
| 7 | 两种组织的立方体 → 多层 | 各层参数；层间界面 | 逐单元材料 SOFA 原生支持；界面刺穿要自己加 |
| 8 | 柔性针 | 到这一步再定模型 | — |
- 速度（实时）每一步都检查。
- 已知的问题和依据见 `docs/code/01–04`。

- 复核后加入的两条要求（2026-09-30）：
  1. **0d 是进入第 1 步的关卡**：0d 结束时要冻结一个可以进入第 1 步的实时配置（网格 / dt / 求解路线的最小选择），不做长期性能研究。判定标准在 0d 设计里定；至少要在"针 + 接触约束"的代表性工况下满足每步计算时间 ≤ dt，否则由用户明确接受一个 RTF。
  2. **第 1 步的接触验证参照要用相同的离散接触雅可比**（same mesh + same contact Jacobian）：
     - 先让针尖正好接触顶面中心的一个表面顶点（重心坐标 = (1,0,0)，法向 = z，位置对称，不会侧向漂移），比较单边接触和同一顶点给定法向位移；
     - 再测三角形内部的接触：用相同的重心权重 w 构造运动学参照。例如先用静力解求出三个节点之间的 z 向柔度矩阵 C，参照刚度取 k_ref = 1/(wᵀCw)，再和接触求解的结果比较（动力学下比较 W 时要用同样的 H）。
