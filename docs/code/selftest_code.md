# 代码层面的应用自测（E3，14 题）

> 每题要求：能用代码位置（文件:行号）或运行结果作答，并能据此推出对项目的具体做法。依据见 `docs/code/01–04`、`handbook.md §12`。

---

**1. 在官方场景里，把 `ConstraintInsertion.frictionCoeff` 从 0.002 改成 0.2，针根感受到的轴向阻力会变成多少？为什么没法事先给出一个"物理"答案？**
取决于 GS 的 tolerance、maxIt 和约束数：tol = 1e-5 时约 48 N（针根一侧），tol = 1e-8 时约 51 N（完全粘住），maxIt = 2 时约 21 N。因为 `InsertionResolution::resolution()` 里 `corr[0] = frictionCoeff × (−invW·d)[0]`，这只是轴向更新的欠松弛；GS 每步从 λ = 0 开始（`FullVector.inl:100-111`），停止判据是 Σ‖WΔλ‖ < tol × 约束数（`BlockGaussSeidelConstraintSolver.cpp`）→ 阻力 ≈ (1 − (1 − μ)^k) × 粘住力，k 是迭代次数。〔01 问题 1，实验 1〕

**2. 官方场景里针根测到的刺穿力是 16 N，组织实际受到的力是多少？如果把 dt 减半，两者各变成多少？**
组织约 1647 N（= λ/dt），针根 16.4 N（= λ，因为针是 `firstOrder=True`）。dt 减半后：组织仍约 1643 N（阈值就是按组织一侧的力定义的），针根变成 8.2 N。根源：W 的积分因子 = dt（`BaseConstraintCorrection.cpp:54-74`），二阶物体把 λ 当冲量，一阶物体把 λ 当力。〔01 问题 2，实验 2、3〕

**3. 要让针根的力可以和实验（机器人力传感器）直接比较，场景该怎么改？**
针和组织用同一种积分器（都用二阶 `EulerImplicitSolver`）；读力时用 λ/dt，或者直接读针根弹簧的力。实验 11：二阶针数值稳定、作用力 = 反作用力，但针根要固定得更牢（或者表面接触要有摩擦），否则刺穿前针尖会在表面上滑开。〔01 问题 2，02 B2〕

**4. 组织单元约 20 mm 时，`tipDistThreshold` 应该设多少？如果坚持设 3 mm 会怎样？**
设为约 20 mm（不小于单元尺寸），同时考虑针单元长度（Baksic 2022：三个不共线的约束作用在同一个梁单元上会过约束）。3 mm 会严重过约束：容差收紧时 GS 每步都达不到收敛（实验 9：50 mm 单元、3 mm 间距时每步 5001 次迭代）；默认的松容差会把这个问题掩盖掉，但结果的"摩擦"就变成了数值副产品。〔04 实验 9〕

**5. 刺穿判定在代码里用的是什么量？和 Duriez 2009 的三状态律有什么区别？**
`InsertionAlgorithm.cpp:179-193`：在 `AnimateBeginEvent` 时读上一步存下的针尖 λ（运动空间），把各分量的范数相加，除以 dt，和阈值比较。区别：①用的是合力（包括切向摩擦），不是法向力；②滞后一步，阈值不在约束律里 → 刺穿那一步力可能超过阈值；③超过阈值后直接切换状态，没有 Duriez 那种"λ 截断在 f_p、δ ≤ 0"的阶段。

**6. 刺穿之后，针尖前进时受到的阻力来自哪里？**
只来自针身约束点的轴向"摩擦"（问题 1 的数值摩擦）。刺穿后碰撞输出被清空（`InsertionAlgorithm.cpp:110`），针身碰撞也跳过（L124）→ **针尖没有任何约束，也没有切割力**。

**7. 一个网格里分上下两层材料，用现有插件会得到什么行为？还缺什么？**
SOFA 的线弹性四面体力场可以给 `youngModulus` 一个长度等于四面体数的向量（`BaseLinearElasticityFEMForceField.inl:126-149`）→ 两层的刚度差异能正确体现；约束点可以落在任意四面体上（`InsertionAlgorithm.cpp:333-346`）→ 可以一路插进第二层。**缺的**：层间界面不会触发刺穿事件（只检测 `surfGeom`）；两层的摩擦、切割参数不能分别设置（插件只有一个全局 frictionCoeff）。

**8. 要算 Wang 2025 代价函数里的组织应变能，能不能直接用 `node.computeEnergy()`？**
不能。`FastTetrahedralCorotational` 和 `TetrahedralCorotational` 的 `getPotentialEnergy()` 直接返回 0（`.h` 里写着 "not implemented yet"）；`TetrahedronFEMForceField` 只在 `method="small"` 时计算。`computeEnergy()` 返回的势能只包含重力和弹簧〔实验 7〕。要用每个单元的旋转、刚度矩阵和位移自己算。

**9. CE 采样需要从同一个状态出发做很多次前向仿真，怎么实现？**
进程分叉快照：父进程停在当前状态，每个样本 `os.fork()` 一个子进程去模拟。实验 6 确认：结果逐位可重复，插件内部的约束点状态（C++ 私有成员）一起被复制，多个分支可以并行。代价是内存（每个进程一份，写时复制）。

**10. 把网格从 216 个节点加密到 4096 个节点，每步耗时会怎样？瓶颈在哪？**
从约 3 ms 增加到约 1.7 s（实验 10，约按节点数的 2 次方以上增长）。瓶颈：官方配置每步重新分解 `EigenSimplicialLDLT`（组织矩阵每步都变，因为是共旋），W 要对每个约束行回代一次（组装 W 占 58%，实验 / 02 B8）。改进方向：预计算柔度（`PrecomputedConstraintCorrection`，需要 dt 固定、线性或小变形）、迭代求解器 + 预条件器、降阶。

**11. 如果 Manish 要求用 Cosserat 杆做针，现成的资源能提供什么，还缺什么？**
Cosserat 插件可以在 v25.12 上编译（要本地 pybind11 2.12、禁用 SoftRobots、`PYBIND11_BUILD_ABI=_cxxabi1016`）。它的针示例能运行（要修两处示例代码），但只是原型：插入方向写死为 x 轴，轴向没有摩擦，深插入时力振荡。**缺的**：把 CollisionAlgorithm 那套交互（或我们重写的版本）接到 Cosserat 杆上。〔03 C1〕

**12. 能不能直接用 SoftRobots.Inverse 的 `QPInverseProblemSolver` 做针插入的闭环控制？**
不能直接用：它把所有非 SoftRobots 类型的约束都当作"接触"（单边 + 摩擦，`QPMechanicalSetConstraint.cpp:70-115`），针插入的双边约束会被错误处理。要么把针的约束改写成 SoftRobots 的等式约束，要么修改分类逻辑。另外它是 AGPL-v3 并附带专利。〔03 C2〕

**13. v25.12 tag 和上游 master，应该用哪个？**
两者在我们的实验里结果完全相同（实验 4），master 也能在 v25.12 上编译（02b）。master 多了：拔出时检查针尖速度方向、`contactDistance`、柔度块缩放求逆。**但两者都没修问题 1（数值摩擦）、问题 5（带摩擦的单边约束 GS bug）**。建议：以 v25.12 为基础，合入 master 的修复和 ICube 的 GS 修复（`3e83cc4`），再加我们自己的修改。

**14. 如果要复现 Okamura 的"刺穿峰值 → 骤降 → 线性增长"，基于现有插件至少要改哪些地方？**
①针和组织用一致的积分器（问题 2）；②刺穿判定改用法向力；③刺穿后给针尖加切割阻力（Bui 的针尖约束，λ_c0 < 刺穿阈值 → 才会出现骤降）；④把 `InsertionResolution` 的轴向改成有物理量纲的摩擦律（固定阈值 N/m × l_k，或者 handbook §4 的统一形式），而不是欠松弛；⑤约束间距 ≥ 单元尺寸，GS 容差收紧到真正收敛；⑥在固定网格下标定参数（实验 10）。
